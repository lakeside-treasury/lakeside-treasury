How it works

  • The board view shows the spreadsheet for every fiscal year, the summaries for the board if you include them, and a button to download the Excel workbook.
  • Once it's published, it updates itself whenever you save a statement, a budget or a board summary. GitHub takes a minute or two to show the change.
  • The copy is encrypted with the viewer password and stored in the public app repository, so anyone with the link still needs the password. Because the encrypted file is public, use a password of 10 or more characters that isn't used anywhere else.
  • Send the link and the password separately. Changing the password locks out the old one at the next update; Stop sharing removes the copy entirely.

Handoff & security

Handing over to a new treasurer

  1. The new treasurer makes a free GitHub account, and you invite them to the treasury organization as an Owner (GitHub → the organization → People → Invite member).
  2. They create their own access token for the data repository (README, step 3) and open this page on their computer.
  3. Give them the passphrase in person or by phone, never in the same message as anything else.
  4. Once they're in, have them change the passphrase below to one only they know. If the board view is shared, they can keep its viewer password or set a new one on the Board view page.
  5. Then remove yourself from the organization, and delete your own access token on GitHub.

Monthly routine

  1. When the bookkeeper's statement arrives, open Statements and drop in the PDF.
  2. Check any data warnings, then save.
  3. Read the Brief, add your notes, and copy it into the board email.
  4. The board view, if shared, updates itself. Otherwise download the Excel workbook for the board.
  5. Each year, when the board approves the new budget, enter it on the Budget page.
  6. When GitHub emails that your token is about to expire, make a new one and choose "Use a different repository or token" on the unlock screen.

Change passphrase

Re-encrypts every statement with the new passphrase. Takes a few seconds.

Encrypted backup

A single file holding every statement, note and summary, still encrypted with the current passphrase. GitHub already keeps every version, but a yearly copy on the school's shared drive is cheap insurance.

How the data is protected

  • Each statement is encrypted in your browser with AES-256-GCM before it is sent to GitHub. The key comes from the passphrase (PBKDF2-SHA-256, 600,000 rounds) and is never stored or sent anywhere.
  • The private repository holds only ciphertext, plus the month each file covers (for example statements/2025-09.json) and the commit history of when things were saved.
  • Your GitHub token is stored on this device only if you ticked "Remember", and then only encrypted with the passphrase. Locking the page clears it from memory.
  • The page locks itself after 20 minutes without activity, and whenever it's closed.
  • The app's code is public; the books are not. Nothing in the code is secret.
  • A forgotten passphrase can't be reset. Keep a backup and keep the passphrase with the school's important records.
